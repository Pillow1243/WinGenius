# WinGenius 4.0 — چه چیزی عوض شد

> نسخه‌ی ۱ «مجموعه ابزار» بود، نسخه‌ی ۲ «موتور» شد، نسخه‌ی ۳ **دستیار** شد.
> نسخه‌ی ۴ سه چیز را اضافه می‌کند که هیچ‌کدام از آن‌ها را نداشت:
> **امنیت داده** (گاوصندوق رمزدار)، **بازگشت‌پذیری** (هر تغییر فایل با `Ctrl+Z` برمی‌گردد)
> و **تکرار خودکار** (زمان‌بند cron، ماکروهای شرطی و API محلی).

---

## ۲. پنج قابلیت اصلی نسخه ۴

### الف) گاوصندوق رمزدار («امنیت» → شش ابزار)

فایل `.wgv` ساده و قابل حمل: **AES-256-GCM** برای داده‌ها و `PBKDF2-HMAC-SHA256` با
**۲۴۰٬۰۰۰ تکرار** و salt تصادفی ۱۶ بایتی برای کلید.

- هر فایل یا یادداشت **nonce مستقل** دارد؛ یعنی هیچ دو رکوردی هم‌شکل رمز نمی‌شوند.
- نوشتن **اتمیک** است (`*.wgv.tmp` + `os.replace`)، پس قطع برق فایل را نصفه نمی‌کند.
- «تغییر رمز» فقط هدر را عوض نمی‌کند؛ **همه‌ی محتویات با کلید تازه از نو رمز می‌شوند**.
- «فهرست» هر رکورد را رمزگشایی و **سلامت** آن را تأیید می‌کند؛ رمز اشتباه پیام روشن
  «رمز اشتباه است یا فایل آسیب دیده» می‌دهد (بدون افشای هیچ بایتی).
- ساختار فایل: `WGV1 | salt16 | iterations(>I) | nonce12 | len(>I) | ciphertext`.

ابزارها: `vault_create` · `vault_add` (فایل یا یادداشت) · `vault_list` · `vault_extract` ·
`vault_remove` · `vault_password`.

### ب) ژورنال و بازگردانی (`Ctrl+Z`)

تغییر نام گروهی، «مرتب‌سازی خودکار فایل‌ها» و «صاف‌کردن پوشه» قبل از هر تغییری در
**ژورنال SQLite** ثبت می‌شوند (به‌همراه snapshot سبک وقتی فایل کوچک است).

- `Ctrl+Z` (یا دکمه‌ی داشبورد) **آخرین عملیات را عیناً برمی‌گرداند**: نام‌ها، مسیرها و پوشه‌های ساخته‌شده.
- هر عملیات وضعیت `pending / done / undone / failed` دارد؛ خطاها دقیق گزارش می‌شوند و بقیه‌ی
  عملیات متوقف نمی‌شود.
- حذف‌ها به **سطل بازیافت داخلی** (`trash\`) می‌روند و با `trash_restore` برمی‌گردند؛
  پاک‌سازی سطل فقط با تأیید صریح انجام می‌شود.
- داشبورد بخش تازه‌ی **«آخرین عملیات (Ctrl+Z)»** را نشان می‌دهد: عنوان، ساعت و این‌که آیا
  هنوز قابل بازگردانی است.

ابزارها: `undo_last` · `undo_history` · `trash_move` · `trash_restore` · `trash_cleanup`.

### ج) زمان‌بند cron (`Ctrl+5`)

- عبارت cron معتبرسنجی می‌شود (`*`, `*/n`, بازه، فهرست) و **به فارسی خوانده می‌شود**:
  «هر ۱۵ دقیقه»، «شنبه‌ها ۰۸:۰۰». سه پیش‌فرض آماده هم در فرم هست.
- هر زمان‌بندی هدفش یکی از این‌هاست: **گردش‌کار**، **ابزار** یا **ماکرو**.
- **جبران اجرای ازدست‌رفته**: اگر سیستم خاموش بود، اولین تیک بعد از باز شدن برنامه اجرای
  فوت‌شده را انجام می‌دهد (قابل خاموش کردن برای هر زمان‌بندی).
- کارت هر زمان‌بندی: «بعدی: …»، تعداد اجرا، آخرین وضعیت، و دکمه‌های اجرای فوری/خاموش‌روشن/حذف.
- «برنامه» (Agenda) نزدیک‌ترین اجراهای همه‌ی زمان‌بندی‌ها را یک‌جا نشان می‌دهد.
- موتور `Scheduler` با `QTimer` هر ۱۵ ثانیه تیک می‌زند و فقط وقتی لازم است روشن می‌شود
  (اگر هیچ زمان‌بندی فعالی نباشد، خاموش می‌ماند).

### د) موتور ماکرو شرطی

یک DSL کوچک و خوانا برای کارهای تکراری چندمرحله‌ای:

```json
{
  "name": "مرتب‌سازی دانلودها",
  "vars": {"src": "C:/Users/me/Downloads", "dst": "C:/Archive"},
  "steps": [
    {"type": "mkdir", "path": "{dst}"},
    {"type": "foreach", "glob": "{src}/*.pdf", "as": "f", "steps": [
      {"type": "if", "test": "exists", "path": "{f}",
       "then": [{"type": "run", "tool": "pdf_compress", "values": {"src": "{f}", "mode": "strong"}}],
       "else": [{"type": "log", "message": "پیدا نشد: {f}"}]}
    ]},
    {"type": "write", "path": "{dst}/report.txt", "text": "تمام شد"}
  ]
}
```

- گام‌ها: `copy`, `move`, `delete`, `mkdir`, `write`, `run` (ابزار), `workflow`, `foreach`, `if/else`,
  `sleep`, `log`. متغیرها با `{name}` جای‌گذاری می‌شوند و glob پشتیبانی می‌شود.
- **اعتبارسنجی** قبل از اجرا: نوع گام ناشناخته، ابزار ناموجود، متغیر تعریف‌نشده.
- **اجرای تمرینی** (`dry_run`): همه‌چیز شبیه‌سازی می‌شود، هیچ فایلی ساخته یا پاک نمی‌شود،
  و تعداد گام‌های «اجراشده» گزارش می‌شود.
- سه قالب آماده با یک کلیک در شیت زمان‌بند ساخته می‌شوند (PDF اسکن‌شده → جست‌وجوپذیر،
  بسته‌ی عکس‌ها، پاک‌سازی دانلود). ذخیره‌ی دوباره، فایل تکراری نمی‌سازد.

### ه) API محلی JSON

سرور کوچک روی `127.0.0.1` (پورت دلخواه، پیش‌فرض تصادفی) با **توکن اجباری**:

| مسیر | کار |
|---|---|
| `GET /health` | نسخه، تعداد ابزار، وضعیت |
| `GET /tools?q=&category=` | جست‌وجو در ۲۴۶ ابزار |
| `GET /tools/<id>` | فیلدها و پیش‌فرض‌های یک ابزار |
| `GET /workflows` | گردش‌کارها |
| `GET /plan?q=…` | یک جمله ⇒ زنجیره‌ی پیشنهادی |
| `POST /run {tool, values}` | اجرای واقعی ابزار |
| `GET /journal` · `POST /undo` | ژورنال و بازگردانی |

بدون توکن: `401`. مسیر ناشناخته: `404`. ابزار ناشناخته: `404` با پیام روشن.
توکن در `%APPDATA%\WinGenius\api_token.txt`. با `--serve --port 8770` هم از CLI بالا می‌آید.

## ۳. تغییرات رابط

- ریل ناوبری **پنج** دکمه دارد: داشبورد، برنامه‌ریز، گردش‌کارها، خودکارسازی، **زمان‌بند** (`Ctrl+1..5`).
- پالت دستورها چهار فرمان تازه دارد: `scheduler`، `undo`، `vault`، `api`.
- داشبورد: بخش **«آخرین عملیات (Ctrl+Z)»** با چهار ردیف و دکمه‌ی «بازگردانی آخرین عملیات».
- اصلاح دو نکته‌ی ظاهری که در نسخه‌ی ۳ دیده می‌شد:
  - متن‌های ترکیبی فارسی/لاتین (مثل `PDFهای اسکن‌شده`) با **علامت راست‌به‌چپ** شروع می‌شوند تا
    ترتیب کلمات به‌هم نریزد.
  - شماره و واحد (مثل `19.4 GB`) داخل جمله‌ی فارسی با **ایزوله‌ی یونیکد** بسته می‌شوند تا
    `GB 19.4` نشود؛ میترهای CPU/RAM/Disk هم هر کدام خط خودشان را گرفتند.
- ۱۰ آیکون تازه (`undo`, `play`, `check`, `calendar`, `heart`, `bell`) — همه وکتوری، بدون فونت.

## ۴. CLI تازه

```bat
WinGenius.exe --list-schedules
WinGenius.exe --run-schedule <id>
WinGenius.exe --macros
WinGenius.exe --undo
WinGenius.exe --serve --port 8770
```

همه‌ی این‌ها همان موتور برنامه‌اند (نه مسیر دوم و جدا)، پس هر چیزی که در UI کار می‌کند،
در اسکریپت و Task Scheduler هم همان‌طور کار می‌کند.

## ۵. تست‌ها و بازبینی

| مجموعه | نسخه ۳ | نسخه ۴ | چه چیزی تازه پوشش داده شد |
|---|---|---|---|
| `smoke_test.py` | ۱۲۹ | **۱۵۴** | گاوصندوق دور کامل (ساخت/افزودن/استخراج/تغییر رمز/حذف + نبود متن ساده روی دیسک)، ژورنال و سطل، زمان‌بند، ماکرو، API روی HTTP واقعی |
| `functional_test.py` | ۲۱۳ | **۳۵۷** | گروه‌های `journal`, `scheduler`, `macro`, `vault`, `api` + سه گروه شکار باگ `schema`, `stress`, `fuzz` |
| `ui_test.py` | ۹۳۹ | **۱٬۰۳۵** | پنج شیت، ذخیره/حذف زمان‌بندی از دل شیت، بازگردانی واقعی با `Ctrl+Z`، روشن/خاموش API |
| **جمع** | ۱٬۲۸۱ | **۱٬۵۴۶** | همه PASS، صفر خطا |

باگ‌هایی که همین تست‌ها پیدا کردند و اصلاح شدند:

1. `change_password` هدر را عوض می‌کرد ولی محتویات را با کلید قدیم می‌گذاشت ⇒ بعد از تغییر رمز،
   استخراج شکست می‌خورد. حالا همه‌ی رکوردها با کلید تازه از نو رمز می‌شوند.
2. `unlock` تعداد تکرار PBKDF2 را از فایل نمی‌خواند و با مقدار پیش‌فرض می‌نوشت ⇒ گاوصندوقِ
   ساخته‌شده با تکرار کم، بعد از اولین ذخیره خراب می‌شد.
3. `vault_add` وقتی مسیر فایل به‌صورت رشته می‌آمد (CLI/API) هر نویسه را یک فایل می‌دید.
4. `/plan` در API به فیلد `args` اشاره می‌کرد که در `Step` وجود ندارد (`values` درست است) ⇒ ۵۰۰.
5. دکمه‌های «ذخیره/فرم تازه» در شیت زمان‌بند تا اولین تغییر زبان خالی بودند، و فهرست هدف
   به‌درستی پر نمی‌شد.
6. ذخیره‌ی دوباره‌ی قالب ماکرو، فایل‌های `…-2.json` و `…-3.json` می‌ساخت.
7. میترهای داشبورد سه خط را روی هم می‌انداختند (حداقل ارتفاع ثابت ۳۴ پیکسل).

## ۵.۱. شکار باگ: سه تست تازه که عمداً خرابکاری می‌کنند

| گروه | روش | نتیجه |
|---|---|---|
| `schema` | بازبینی همه‌ی ۲۴۶ ابزار: آیکون موجود در مجموعه، دسته‌ی معتبر، نام و توضیح فارسی/انگلیسی، کلید یکتا، گزینه‌های برچسب‌دار، پیش‌فرض داخل گزینه‌ها، `visible_when` معتبر، پیدا شدن ابزار با نام خودش در جست‌وجو، و رسیدن هر ۳۱ نیت برنامه‌ریز به ابزار واقعی | **۲۴ ابزار آیکون ناموجود داشتند** و بی‌صدا «چرخ‌دنده» می‌گرفتند → ۲۰ آیکون وکتوری تازه ساخته شد |
| `stress` | داده‌ی ۴ مگابایتی در گاوصندوق، ۵۱ رکورد، ۶۰ فایل در یک تغییر نام، کرون ۲۹ فوریه، فایل زمان‌بندی خراب، ماکروی ۴۰۰ مرحله‌ای، ۲۴ درخواست هم‌زمان HTTP، JSON ناقص، توکن غلط | هدر آسیب‌دیده‌ی گاوصندوق `ValueError` می‌داد، «۲۹ فوریه» پیدا نمی‌شد، شمارنده‌ی گام ماکرو در اجرای واقعی صفر بود |
| `fuzz` | هر ۲۴۶ ابزار با سه دسته ورودی (پیش‌فرض، خالی، مسیر مخرب `../../..`) و بررسی این‌که پیام خطا هرگز `Traceback`/`KeyError` نشان ندهد | **۳۰ ابزار با ورودی نامناسب کرش می‌کردند** — همه اصلاح شدند |

اصلاحات مهم این مرحله:

1. **گارد سراسری ابزار** در `registry.register` — هر خطای پیش‌بینی‌نشده به پیام دوزبانه تبدیل می‌شود
   (traceback فقط در لاگ). هیچ ابزاری دیگر برنامه را نمی‌بندد.
2. **پیمایش امن** — `list_files`/`walk_files`/`safe_is_file` پوشه‌های بدون دسترسی را رد می‌کنند
   (قبلاً `PermissionError` از `/proc` کل ابزار را می‌شکست).
3. **رد کردن ریشه‌ی دیسک** با پیام روشن، به‌جای چند دقیقه اسکن بی‌فایده.
4. **`read_text_file` و `text_or_file`** — پیام «این یک پوشه است»/«اجازه ندارید» به‌جای `IsADirectoryError`.
5. **اعتبارسنجی میزبان** برای ابزارهای شبکه (`UnicodeEncodeError: 'idna'` حذف شد).
6. **گاوصندوق**: بررسی محدوده‌ی تکرارهای هدر و طول داده، پیام «فایل ناقص/آسیب‌دیده»،
   و کلید‌سازی با تکرارهای ثبت‌شده در فایل.
7. **کرون**: جست‌وجوی هوشمند زمان بعدی (پرش ساعت/روز) — «۲۹ فوریه» در ۰٫۰۲ ثانیه و درست.
8. **ژورنال**: `stats().undone`، و سطل بازیافت هرگز فایل زنده را بازنویسی نمی‌کند.
9. **ماکرو**: `MacroResult.message` دوزبانه، شمارش گام در اجرای واقعی، و ذخیره‌ی تکراری‌ناپذیر.
10. **آیکون‌ها و متن**: ۲۰ آیکون تازه، علامت راست‌به‌چپ برای متن‌های ترکیبی، ایزوله‌ی یونیکد برای
    واحدها (`19.4 GB`)، و میترهای داشبورد که هر کدام خط خودشان را دارند.
11. **شبح متن در شیت‌ها**: افکت شفافیت بعد از پایان انیمیشن محو‌شدن برداشته می‌شود و لبه‌ی
    اسکرول گرادیان نرم می‌گیرد — با اسکرول بدنه دیگر خط نیمه‌بریده زیر سرتیتر دیده نمی‌شود.
12. **کتابخانه‌ی ماکرو بدون تکرار**: `macro.library()` برای هر نام یک فایل برمی‌گرداند
    (قبلاً `-2`، `-3`، `-4` روی هم جمع می‌شدند و CLI دوازده ماکرو نشان می‌داد به‌جای سه).
13. **راهنمای کرون**: توضیح و «بعدی: …» در دو خط جدا؛ `describe_cron` هم برای «هر روز / هر ساعت»
    عبارت درست می‌دهد و اعداد لاتین دیگر داخل جمله‌ی فارسی درهم نمی‌شوند.
14. **پرده‌ی پشت شیت**: تیرگی ۶۲٪ → ۷۴٪ تا متن پشت شیت خوانده نشود.
15. **zip-slip**: `zip_extract` مسیرهای فرارگر را رد می‌کرد اما `extractall()` دوباره همه را می‌نوشت؛
    حالا عضو‌به‌عضو استخراج می‌شود، مسیرهای خارج از مقصد رد و گزارش می‌شوند.


## ۶. چه چیزی عوض *نشد*

- همه‌ی ۲۲۵ ابزار نسخه‌ی ۳ سر جایشان هستند؛ شمارش از ۲۲۵ به ۲۴۶ رسید و هیچ ابزاری حذف نشد.
- هیچ پردازش جدیدی داده‌ای به اینترنت نمی‌فرستد: گاوصندوق، ژورنال، زمان‌بند و ماکرو کاملاً محلی‌اند
  و API فقط روی `127.0.0.1` گوش می‌دهد.
- سیاست «اگر کتابخانه نبود، پیام نصب بده، نه کرش» برای همه‌ی ابزارهای تازه هم رعایت شده
  (گاوصندوق بدون `cryptography` پیام نصب می‌دهد).
- فارسی همچنان زبان اول است و انگلیسی یک کلید فاصله دارد (همه‌ی رشته‌های تازه دوزبانه‌اند).

## ۷. اجرا

```bash
pip install -r requirements.txt
python main.py                    # رابط کامل
python main.py --serve --port 8770 # فقط API
python main.py --list-schedules    # زمان‌بندی‌ها از CLI
python main.py --undo              # بازگردانی آخرین عملیات
```

تصاویر این نسخه با `QT_QPA_PLATFORM=offscreen python packaging/make_screenshots.py`
از خود برنامه گرفته شده‌اند (۲۹ تصویر) و صفحه‌ی معرفی مستقل در `docs/showcase.html` است.
