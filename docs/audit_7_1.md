# WinGenius 7.1 — Comprehensive Technical Audit & Hardening Architecture Report

**Baseline Audited:** `v7.0.0` (`9c864f8`)  
**Audit Date:** 2026-11-04  
**Scope:** Full repository static & runtime audit across `main.py`, `app/bootstrap.py`, `app/core/` (35 modules), `app/ui/` (16 modules), `app/tools/` (45 modules, 270 registered tools across 15 categories), `packaging/` (8 files), `scripts/` (6 files), `.github/workflows/` (4 workflows), `tests/` (8 suites), and all Persian/English documentation (~46,417 Python lines).

---

## 1. Executive Summary

WinGenius `7.0.0` has a clean baseline (`ruff check` clean, 77% test coverage, Persian PDF/HarfBuzz engine, and Node 24 CI action pinning), but deep line-by-line inspection across every execution surface (GUI, Background Queue, CLI, Workflows/Flowkit, Macros, Scheduler, Folder Watcher, and Loopback HTTP API) uncovered **critical security, architectural, concurrency, UI/RTL/accessibility, and performance issues** that must be remediated systematically for `7.1.0`:

1. **Fragmented Execution Surfaces & Policy Bypass (`P0`/`P1`):** Tool execution is currently duplicated across 9 call sites (`registry.invoke`, `worker.ToolRunner`, `jobs.JobCenter`, `cli.py`, `workflows.py`, `flowkit.py`, `macro.py`, `planner.py`, `api_server.py`) with only a coarse static `spec.danger: bool` flag. Action-dependent destructive/elevated operations (e.g., `process_manager(action=kill)`, `installed_apps(action=uninstall)`, `scheduled_tasks(action=delete)`, `folder_sync(mode=mirror)`, `ocr_setup(action=set_path)`, `startup_add`, `env_vars(action=set_user)`) are marked `danger=False`, and `api_server.py` allows `flow_run`, `macro_run`, and `/undo` to bypass `allow_dangerous`.
2. **Command, PowerShell, Flag & Protocol Injection (`P0`):** Unescaped single-quoted string interpolation into `powershell -Command` (`windows_tools.py`, `windows_extra.py`), `cmd /c start` metacharacter execution (`launcher.py`), `ping`/`tracert` option flag injection (`network_tools.py`, `network_extra.py`), CRLF injection in raw HTTP timing sockets (`network_extra2.py`), and unvalidated `lang`/`model` parameters in OCR/Whisper (`ocr_tools.py`, `media_extra.py`).
3. **Loopback API, Vault, Archive & Symlink Escapes (`P0`):** Keep-alive request smuggling/desync on `Transfer-Encoding: chunked` or negative `Content-Length`, missing `Origin`/`Sec-Fetch-Site` browser request rejection, `Vault.extract()` collision suffix bypass of `_safe_entry_name`, symlink-following file shredding in `secure_delete`, missing ZIP-bomb/symlink guards in `zip_extract`/`archive_decrypt`, path traversal in `checksum_manifest`/`qr_generate`/`download_file`/`create_shortcut`, and unauthenticated legacy `WGF1` decryption fallback in `text_encrypt`.
4. **Privacy, Secret Redaction & Plugin Provenance (`P0`):** Raw secret output in `secret_scan` and `env_vars(list)`, plaintext `.env` indexing and symlink traversal in `indexer.py`, `ClipboardWatcher` capturing sensitive clipboard changes while paused, missing `macros/` backup & unsafe raw copy of live SQLite WAL databases, and incomplete plugin trust lifecycle (`untrust_plugin`, provenance metadata, symlink rejection).
5. **Headless CLI Purity, Thread Lifecycles & Tool Correctness (`P1`):** Eager `PySide6.QtGui`/`QtWidgets` imports in `app/bootstrap.py` and `app/tools/image_watermark.py`, `cli.py` ignoring `--dry-run` on `--run` and failing on `--plan` and `macro` schedules, leaked `QThread` instances in `WorkflowRunner` and `MainWindow`, `ffmpeg` stderr pipe deadlock risk, single-page limit in `pdf_forms_fill`, and 11 tools bypassing `save_target`/`out_dir`.
6. **UI/UX, Contrast, RTL & Accessibility (`P2`) and Performance (`P3`):** Global `outline: 0` removing keyboard focus indicators, `daylight` theme WCAG contrast failures, LTR-hardcoded `QComboBox`/`QMenu` stylesheet padding, `RadialMenu` running a 62.5 FPS timer while hidden and lacking keyboard navigation, `QuickSearch` landing on section headers, `Dashboard` blocking the GUI thread 50 ms per poll (`cpu_percent(0.05)`), repeated multi-MB TTF reloads in `persian_pdf.py`, and eager RAM allocation in `images_to_pdf` and `image_exif(strip)`.

## 3. Target Architecture: Unified `ExecutionService`

```text
  GUI (ToolPanel) ──┐
  JobCenter Queue ──┤
  CLI (--run/plan) ─┤                                 ┌─► Input Validation & Secret Scrubbing
  Workflows/Flows ──┼──► ExecutionService.execute() ──┼─► Dynamic Risk Classification
  Macros          ──┤    (app/core/execution.py)      │     SAFE | CONFIRM | DESTRUCTIVE | ELEVATED
  Scheduler       ──┤                                 ├─► Caller ExecutionPolicy Gate + Dry-Run
  Folder Watcher  ──┤                                 ├─► Cancellation & Timeout Context
  Loopback API    ──┘                                 └─► Unified History + Undo Journal + Audit Log
```

### Operation Risk Tiers
1. **`SAFE`:** Read-only analysis, format conversion to a new file (`unique_path`), text/PDF/image transformations that do not overwrite existing user data, system inspection without secrets.
2. **`CONFIRM`:** Operations that reveal sensitive local secrets (`wifi_passwords`, `bitlocker_status(recovery)`), install packages (`winget_tool(install/upgrade)`), terminate user processes (`process_manager(kill)`), or modify user environment/startup entries (`startup_add`, `create_shortcut(where=startup)`, `env_vars(set_user)`).
3. **`DESTRUCTIVE`:** Irreversible deletion, shredding, in-place overwrite, mirror-deletion sync, registry/task deletion, app uninstallation, vault mutation, or custom binary persistence (`secure_delete`, `junk_scan(clean)`, `empty_file_finder(delete)`, `empty_folders(delete)`, `folder_sync(mirror)`, `scheduled_tasks(delete)`, `installed_apps(uninstall)`, `startup_manager(delete)`, `ocr_setup(set_path)`).
4. **`ELEVATED`:** Operations requiring Windows Administrator / UAC privileges or modifying OS-wide configuration (`windows_features(enable/disable)`, `restore_point(create)`, `network_repair` admin actions, or any `spec.admin == True` mutating action).

## 4. Auto-Update & Installer Upgrade Audit (`v7.1.0`)

### Findings in `v7.0.0`
- `app/core/updates.py` only implemented a 54-line CLI-only metadata check (`--check-update`). It had no GUI banner or dialog, no changelog viewer, no downloader, no cryptographic signature verification, no installer/portable apply logic, and no rollback mechanism.
- `packaging/installer.iss` had a stable `AppId` (`{{9B1F3E42-6C7A-4B8E-9E4D-2A77C1D0F3A1}`) and did not touch `%APPDATA%\WinGenius`, but lacked `CloseApplications=yes` / `RestartApplications=yes` / `PrivilegesRequiredOverridesAllowed=dialog commandline`, risking file-lock failures when upgrading a running `WinGenius.exe`.

### Implemented `v7.1.0` Auto-Update Architecture
- **Unified Engine (`app/core/updates.py`) & Signing CLI (`scripts/sign_release.py`):**
  - Detects version and install mode (`installer`, `portable`, `standalone_exe`, `source`) and selects `WinGeniusSetup-<ver>.exe` for installed mode or `WinGenius-<ver>.exe` for portable/standalone mode.
  - Enforces HTTPS + GitHub host/repo pinning across initial requests and every redirect hop (`_SafeGitHubRedirectHandler`).
  - **Independent Cryptographic Verification:** Verifies Windows PE structure (`MZ` + `PE\0\0`), cross-checks `SHA-256` and exact byte size across `update-manifest.json`, `SHA256SUMS.txt`, and GitHub's `asset.digest`, checks Windows Authenticode (`HashMismatch`/`NotTrusted` hard-rejected), and requires either a valid `Ed25519` signature over canonical `update-manifest.json` (verified against `TRUSTED_RELEASE_PUBKEYS` baked into the binary, with version/repo anti-replay binding) or a valid OS-trusted Windows Authenticode signature (`require_signature=True` by default).
  - **User Data Preservation & Rollback:** Creates transactional pre-update backups of both user profile data (`upgrade.backup_data_dir`) and the current `.exe` (`<data_dir>/updates/rollback/`), executes upgrades via an out-of-process PowerShell supervisor (`CloseApplications` Inno Setup or atomic `.exe` swap with `--version` smoke probe and automatic rollback on failure), and exposes manual rollback in GUI and CLI (`--rollback-update`).
- **Non-Blocking UI (`app/ui/update_dialog.py`, `MainWindow`, `SettingsPanel`):**
  - `UpdateCheckWorker(QThread)` & `UpdateDownloadWorker(QThread)` keep the Qt UI 100% responsive with live progress and cancellation, `UpdateBanner` notifies users clearly, `UpdateDialog` renders full Release Notes, and installation requires explicit user confirmation.
